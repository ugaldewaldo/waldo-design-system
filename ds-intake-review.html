Promoted 10 new

Each is live in waldo-ui/src/components/ui/, exported, demoed in index.html and documented in usage-doctrine.yaml.

Page Header

The single highest-value piece here: the DS had no page header, so every prototype re-invented the title row with different type sizes and gaps. The muted suffix is a label, not a control: it disambiguates twin pages (a project's Usage vs the org's) without adding another way to navigate.

Looks like an input, is a button. Typing happens inside the ⌘K palette, so a real input here would trap focus and duplicate the palette's own field. Composes the DS Kbd for the hint.

Secret Field — try the eye and the copy

Reveal and copy are deliberately separate: copying is the common case and shouldn't require putting the key on screen first. Masking is display-only. It defends against a shoulder or a screen recording, not against an attacker.

Folded into existing components 2 changed

The dashboard built these as new components. They aren't. They're variants of things the DS already had, and adding them as components would have been duplication.

Tabs — new size="sm"

The dashboard's "time range" control was a separate component. It's just Tabs at a smaller scale, so Tabs gained a size and the component went away. Two judgment calls I'd flag: the source used squared corners (from its Figma node) and a recessed bg-muted active fill. I kept the DS's full-round and bg-secondary — bg-muted is the recessed/disabled role, so using it for an active state inverts what the token means. The dashboard session tested both side by side and agreed the DS version reads better on the new dark ramp.

Avatar — new EntityAvatar

Tracked entities arrive with three levels of available art: a brand usually has a favicon, an audience or category never does, and a just-created entity has only its name. This walks the chain in one place so every list, chip and table row degrades identically.

Held back 3 not taken

All three are real patterns worth having. None is a lift-and-shift: each needs an API designed before it belongs in the DS, and shipping them half-shaped would be worse than waiting.

Project / org scope switcher

The split control where the name navigates and the chevron opens the switcher (Supabase's model), plus a ✕ that closes the project back to the org. Genuinely new: neither Breadcrumb nor App Header covers it. It is entangled with the dashboard's routing and scenario state, so it's a design task.

Nav Rail

An icon rail that expands to labels on hover over the content, so the layout never shifts, where the DS shadcn Sidebar pushes content instead. The behaviour is sound; it hardcodes its own nav items and its gap-based grouping, so it needs an items API with a group concept first.

Spec Note

The per-screen spec annotation (PRO-2816), globally toggleable. Useful to every prototype, but it's coupled to the dashboard's own spec-notes data file, so it has to ship prop-driven, carrying no content of its own.
